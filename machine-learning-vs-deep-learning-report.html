Artifact Title

Machine Learning vs. Deep Learning

Complete coursework report

Original coursework report by Imad Uddin Sheikh · November 1, 2026. This web version preserves the report’s wording; the Word download retains the original formatting.

Download original report (.docx)

Machine learning (ML) and deep learning (DL) both learn patterns from data. Deep learning is a type of ML that uses neural networks with multiple layers. Traditional ML often uses features defined before training, while deep learning learns layers of features from the data (Indiana Wesleyan University, n.d.). Email spam detection and language translation show why the right choice depends on the task, available data, and computing resources.

Email Spam Detection

A research application of the lesson’s email spam example is detecting fraudulent emails that try to obtain sensitive information. Korkmaz (2026) compared traditional ML and DL using 17,538 emails from a public dataset.

The process starts with emails labeled as fraudulent or legitimate. The labels tell the model whether each training email is fraudulent or legitimate. Before training, the email text must be converted into numbers the model can use. The model learns patterns associated with the labels and applies those patterns to classify emails it has not seen before (Indiana Wesleyan University, n.d.).

Tokenization and feature extraction help prepare the text. Tokenization splits text into smaller pieces. For example, “claim your prize” could become the tokens “claim,” “your,” and “prize.” Features describe measurable characteristics of those pieces, such as how often a word appears. Tokens are therefore the pieces of text, while features provide numerical information about them (The scikit-learn developers, n.d.).

Korkmaz (2026) used term frequency–inverse document frequency (TF-IDF) for the traditional models. TF-IDF assigns word weights based on how often a word appears in an email and how common it is across the collection. Words found in nearly every email receive less emphasis than words that help distinguish one email from others. A higher weight does not automatically mean fraud; the classifier learns how the word weights relate to the labels. A new email goes through the same feature-extraction process before the trained model predicts its category (The scikit-learn developers, n.d.).

The tested traditional methods included Naive Bayes, logistic regression, random forest, and XGBoost. Traditional models reached 98.52% accuracy, while the tested deep models reached a maximum of 97.71% (Korkmaz, 2026). Traditional ML fits this application because the TF-IDF features supported accurate classification. I would choose it here because its best reported accuracy was 0.81 percentage points higher. The tested deep models were less suitable because their more complex representations did not improve accuracy. This conclusion applies to the models and dataset in the study, not every spam filter or deep learning architecture.

Language Translation

Google Translate’s Chinese-to-English rollout in September 2016 is a real-world deep learning application. Google deployed its Google Neural Machine Translation system in its web and mobile apps (Le & Schuster, 2016).

Like the email classifier, the translation system needs numerical input. Google’s system split text into smaller pieces called wordpieces, which can represent whole words or parts of words. These pieces were represented as numbers and processed through a neural network. During training, the network learned from examples of sentences and their translations (Wu et al., 2016).

The system had an encoder and a decoder, each with eight layers. The encoder processed the input and built numerical representations that captured information about the sentence. The decoder used that information to generate the translation one piece at a time. Attention helped the decoder focus on relevant parts of the input while producing each piece. Instead of using calculated TF-IDF word weights, the neural network learned its own numerical representations during training (Wu et al., 2016).

Deep learning fits translation because the meaning of a word can depend on the surrounding sentence. The system must also produce words in an appropriate order. Google’s neural approach considered the entire input sentence, while its previous phrase-based system translated smaller pieces largely independently. That made the previous approach less suitable for Google’s goal of improving sentence translation quality (Le & Schuster, 2016).

The reported results support this choice. In a human evaluation of isolated simple sentences, the neural system reduced translation errors by an average of 60% compared with Google’s previous production system (Wu et al., 2016). Google also used specialized computing hardware to meet its service’s speed requirements. The system still made mistakes, including omitted words and incorrect translations of names and rare terms (Le & Schuster, 2016). I would choose deep learning for this application because the measured improvement supported the added complexity, while recognizing that translations could still need review.

Conclusion

A traditional spam filter can learn useful patterns for a narrow classification task. Translation requires preserving relationships across a sentence, making deep learning a stronger fit. I would choose an approach based on its results and resource needs.
