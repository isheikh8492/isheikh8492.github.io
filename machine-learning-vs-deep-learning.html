Artifact Title

Choosing Between Machine Learning and Deep Learning

Introduction

Choosing an AI approach requires understanding the problem and the evidence supporting the choice. This report, developed for AIML-500: Machine Learning Fundamentals, compares traditional machine learning for email fraud detection with deep learning for language translation. It explains how each approach processes text and why it fits the application examined.

Artifact Description

This research-based report connects the way two systems represent text with the tasks they perform. It uses published findings to explain the choice of approach and the limits of each conclusion.

Sources: Korkmaz’s email study and Google’s neural translation research.

Objective:

Explain the differences between traditional machine learning and deep learning through practical applications, and justify why each approach suits the problem examined.

Process:

This was an individual coursework report. I used email spam detection and language translation from the course lesson as starting points, then examined a fraud-email classification study and Google’s neural translation system.

For each application, I explained the input, how text becomes numerical information, and how the model uses that information. I compared the reported results and connected them to my recommendation. I also kept the conclusions within the evidence: the email study does not establish that traditional machine learning is always better, and the translation example does not show that deep learning eliminates errors.

My contribution is the written comparison and interpretation of published research. The model training and reported experiments were conducted by the cited researchers.

Tools and Technologies Used:

  • Course materials and published research: sources for the concepts, applications, and reported findings.
  • scikit-learn documentation: a reference for explaining tokenization and numerical text features.
  • Comparative analysis: examining each application’s task, text representation, results, and limitations.
  • Codex: assistance adapting the existing report into this portfolio entry and drafting the accompanying reflection.
  • HTML and CSS: presentation of the portfolio entry and readable report.

The technologies discussed include TF-IDF, traditional classifiers, neural networks, wordpieces, and attention. These are subjects of the analysis rather than implementations created for this artifact.

Value Proposition and Audience

Personal Value Proposition:

I turn complex workflows and data into reliable, usable software. This artifact supports that focus by explaining how evidence and task requirements inform a technical decision.

Target Audience:

Artifact-Specific Value Proposition

Unique Value:

This report gives readers two worked examples of how to justify a machine learning approach. It connects the task, the way text is represented, and the published results, helping readers understand why a method fits a particular application.

Readers can use the comparison to ask more focused questions when considering an AI solution: What must the system do? How will its input be represented? What evidence supports the proposed approach? How far can that evidence be generalized?

The artifact adds evidence-based technical comparison to the solution planning and historical explanation demonstrated elsewhere in my portfolio.

Relevance:

The report helps software engineers and technical decision-makers examine the reasoning behind a recommendation and recognize when a result is specific to a dataset or system. It supports my professional focus on connecting technical concepts to practical decisions by giving readers a clear example of that reasoning, with sources they can consult for further detail.
